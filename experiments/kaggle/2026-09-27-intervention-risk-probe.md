## Question and literature boundary

When the same set of typed questions is asked about a state, then one fact in that state changes, can a small edit-aware ranker identify which old answers need refreshing better than old-answer confidence, edit/query similarity, or random routing at the same verification budget?

This is a **systems discriminator**, not a novelty claim. Important pieces already exist: Incremental Transformer reuses cached representations for appended inputs and questions; the September 2026 preprint *Contiguity, Not Importance* studies budgeted repair of stale Transformer KV caches after document edits; NormWorlds-CF already uses solver-verified paired worlds and structured answer-change fields; and *No Universal Signal Predicts Sample-Level LLM Regression* compares sample-level risk signals with confidence under model-version changes. The narrow distinction tested here is **typed output refresh after an input edit**, measured against these cheap routing controls. It remains unvalidated and may be a small or already-known systems variation.

The input slate must repeat the previously scored questions. This experiment does not claim a cache benefit for new questions, arbitrary multi-edit documents, or ordinary one-shot classification.

The generated-record audit and inference screen are content-pinned: generator SHA-256 `0203b3157c322ecf5050af898b71ba8a78512e0bdb1f05e8c42a155c9a5422ae`, generated-record SHA-256 `6612571e3625e412eb24f3549e0d21dd3bcc0a609990a13e34ed3314aaa794d1`, and screen SHA-256 `e73d3784f1dd000b19aeb266734864593e5f450a8a7d04f3bde305a9421aec9c`. The collector rejects any mismatch.

For field $j$, the exact synthetic target is

`changed_j = 1[label_j(before) != label_j(after)]`.

At runtime the ranker receives only cached pre-edit state/query vectors and the new edit vector, plus their edit/query interaction features. The comparator scores are `1 - max_probability(old_head)` (confidence), cosine(edit, query), and a deterministic input-independent hash ordering (random reference). Each router receives the same 10%, 25%, or 50% per-field verifier budget, with stable hash tie-breaking. The selected fields use the same top-five post-edit evidence retriever and frozen NLI verifier. Unrouted fields retain the cached pre-edit output.

For route set $R$, answer-quality change is exactly

`Acc(updated) - Acc(cached) = P(R) × [Acc(verifier | R) - Acc(cached | R)]`.

So predicting an answer flip is only useful if the selected verifier fixes more cached errors than it introduces. Risk recall alone is not evidence of a decision-model improvement. At equal verifier-call budgets, the intervention head also adds edit encoding and ranking work; report the complete path cost.

Also report fresh full shared-head recomputation, direct full-state NLI after the edit, top-five NLI on every field, and non-deployable exact-mask/exact-answer oracles. The oracles are ceilings, never candidate methods.

## Registered outcomes and gates

**Primary outcome:** on the held-out Q=20 fields, change recall at a 25% verification budget. Compare edit-risk routing with confidence-only routing using a paired bootstrap that resamples whole rule-composition groups (2,000 replicates).

The pre-score audit has 74 positives among 4,800 held-out Q20 fields (1.54%). A uniform random 25% selector has expected change recall 25%, or 18.5 selected changed fields; this is a mathematical expectation, while the run reports its deterministic hash-control result. The registered +10-point minimum over confidence corresponds to roughly eight additional changed fields at this sample size. The count screen does not estimate power for the +10-point effect plus positive-bootstrap-lower-bound gate: risk/confidence discordance and group-level variance are unknown until scores exist. Passing the count minimum is not a statistical-power guarantee.

Keep this risk feature for a real-data discriminator only if all conditions hold:

1. At least 50 held-out Q=20 fields changed label across at least 10 held-out rule groups. Otherwise mark the run **inconclusive**; do not change the seed after seeing the model scores.
2. Edit-risk routing improves changed-field recall over confidence routing by at least 10 absolute percentage points, and the 95% group-bootstrap interval for the difference has a lower bound above zero.
3. Report whether risk-gated NLI refresh improves Q=20 answer accuracy over cached answers, its paired group-bootstrap interval, actual route fraction, and CPU p50/p95. If the selected verifier fails to improve cached-answer quality or its added routing work erases the saved NLI cost, do not proceed to model training; inspect a different cheap verifier or stop.

Edit/query cosine and deterministic random routing are secondary controls. Report paired group-bootstrap intervals for risk-minus-cosine and risk-minus-random; no post-hoc threshold selection. Report the top-five evidence any/all recall, NLI truncation count, per-class and bundle-exact accuracy, and exact oracle ceilings to explain failures.

## Timing and memory contract

The Kaggle CPU profile uses 24 held-out state requests per Q value and assumes the old state, per-statement embeddings, old outputs, and repeated question slate are cached. It includes edit encoding/routing, updated evidence-bank handling, selected retrieval, tokenization, and selected NLI scoring; it excludes model download/load and initial state encoding. Direct full-state NLI includes post-edit premise construction and all Q pairs. The Kaggle CPU is a named reference only. Its p95 from 24 requests is unstable and does not establish local-device latency. The whole-process RSS includes the loaded encoders but is not a target-machine 8 GiB qualification.

## Validity limits and next action

The generator is templated symbolic logic with a fixed vocabulary, and this is not a public benchmark. The prior `20260927` generator pass inspected only aggregate change prevalence to check whether a 1,024-state screen would have enough positives: 50 held-out states changed at least one answer, with 85 changed Q=20 fields across 30 held-out rule groups. No predictor or verifier scores were computed for that seed. Before any encoder/verifier scoring, a fresh `20260928` generator pass found 74 held-out Q=20 changed fields across 22 held-out rule groups (51 affected states; 240 held-out states total), so it clears the registered minimum of 50 fields and 10 groups. The aggregate audit, including generator and generated-record hashes, is saved in [`2026-09-27-intervention-risk-power-check.json`](2026-09-27-intervention-risk-power-check.json). The registered run still reuses the same grammar and is therefore only a screening experiment. A passing result must be confirmed on an independently sourced paired-edit workload with verified data rights before any novelty or generalization claim.

The closest public lead is NormWorlds-CF (270 root families, 1,080 paired-world variants, solver-produced answer/support/status change fields). Its task is very close to change supervision; the paper's arXiv license does not by itself establish rights to reuse a separate dataset or code artifact. Audit availability, source and terms before using it. Until then, this probe uses only our own generator.

Do not train a backbone or claim a model win from this run. If its gate passes, the next low-cost step is to audit a rights-clear paired-edit data source and compare the exact output-refresh objective with published incremental/cache-repair baselines. If it fails, archive the result and revise or reject the risk-gated idea.

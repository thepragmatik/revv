# Preregistered frozen class prototype screen

**[Plain explanation](../../docs/start-here.md) · [Frozen token comparison](2026-09-27-frozen-matching.md) · [CER-1 hypotheses](../../docs/ideas.md) · [Codex handoff](../../codex/RESUME.md)**

**Status: complete, 27 September 2026.** The first frozen pilot showed that untrained label-name vectors lost to a fitted lexical classifier and token MaxSim lost to pooled cosine. This screen tests whether training-derived candidate descriptions caused the known-intent gap and whether a small candidate shortlist retains the right answer.

The [first submission](https://github.com/thepragmatik/revv/actions/runs/36293716373) failed before model inference: Kaggle executed only the declared `code_file`, so an auxiliary `frozen_matching.py` import was unavailable. No metric or weights were produced. The collector now submits a self-contained script with the **same registered data, model, measures and budget**; one corrected run is justified by this packaging error.

On the same pinned CLINC source and same cleaned 1,547 development / 1,550 calibration rows, use the *same* frozen MiniLM checkpoint and mean pooling for all inputs. Keep model tokenization at 64 tokens for utterances and 16 for underscore-replaced label text, and record truncation. **Method A:** pretrained label-name embedding. **Method B:** encode all 15,000 official in-scope training utterances; average unit-normalized utterance embeddings within each of 150 labels and normalize the resulting class prototypes. Each class has 100 training rows; no OOS rows fit a prototype. Similarity is cosine in both methods. Development and calibration rows are never used to fit centroids. Dataset SHA, checkpoint revision, GPU and fold sizes are checked before output. Never inspect locked test rows.

Use the same calibration known-only maximum-score 5th-percentile threshold for each method, then report known closed and after-defer accuracy, known defer rate, OOS recall with Wilson 95% intervals. Record known true-label candidate recall at `k=1,2,5,10` *before verification*. Pair methods by case and bootstrap the closed-accuracy delta by true intent label (1,000 resamples). Save hashed example IDs and both predictions without original text. Record the training encode/centroid time, validation batch time, peak PyTorch GPU allocation and exact package versions; these are **not** local CPU per-request latency or entire-process RSS. One private internet-enabled Kaggle T4 kernel, 420-second cap, internal 330-second budget, 14-minute collection window, 25-minute Actions cap; no paid compute.

**Decision gate:** if prototypes recover a meaningful amount of known accuracy relative to both untrained label names and the lexical 82.43% floor, prioritize a shared pooled supervised control and measure candidate-recall ceiling before a cross verifier. If improvement is small or OOS falls sharply, treat label training, calibrated abstention and contextual evidence as separate failure modes. A top-`k` verifier's in-scope accuracy cannot exceed measured candidate recall at that `k`; a prototype cannot solve missing evidence on this single-utterance dataset. Avoid a locked-test win claim or an inference-speed claim from this screen.

## Observed and critical interpretation

The corrected [Actions run](https://github.com/thepragmatik/revv/actions/runs/36293818590) collected `rathworx/revv-prototype-screen/2`; the initial packaging failure above produced no comparable result. [Aggregate raw metrics](2026-09-27-prototype-screen.json) and [1,547 hashed predictions](2026-09-27-prototype-screen-predictions.jsonl) provide the audit trail. Training fit **class means only**, with all pretrained encoder weights frozen. All source, fold and label assertions passed; zero train, validation or label rows were truncated under the specified token limits.

| CLINC development measure | Bare label-name vector | Training-derived prototype | Lexical floor, where measured |
| --- | ---: | ---: | ---: |
| Known closed accuracy, 1,497 rows | 70.94% | **91.12%** (Wilson 95%: 89.57–92.45%) | 82.43% |
| Known accuracy after deferral; defer rate | 69.07%; 4.28% | **88.31%; 4.54%** | 80.69%; 4.21% |
| OOS recall, 50 rows | 64% | **86%** (Wilson 95%: 73.81–93.05%) | 36% |
| Correct known label among top 2 / 5 / 10 | 82.03% / 90.92% / 94.26% | **97.33% / 99.00% / 99.33%** | Not recorded |

On paired known examples, prototype minus label-name **closed accuracy is +20.17 percentage points**; the 1,000-label-cluster bootstrap 95% interval is +15.84 to +24.08. A hashed-case join with the fixed lexical floor shows 192 known examples lexical missed that prototypes answered after deferral, versus 78 in the opposite direction. Among only 50 OOS examples, prototype rejected 28 that lexical missed versus three in the opposite direction. The OOS interval is broad, and no alternate-source generalization is shown. Training utterance encoding and centroid construction took 3.41 seconds on a T4, once; development/calibration batch encoding plus both scorings took 0.55 seconds; model loading took 5.41 seconds. Peak PyTorch GPU allocation was 156,083,200 bytes. These are not entire-process CPU RSS, p50/p95 per-request times or deployment speeds.

**Decision:** the small frozen pooled encoder with fitted class prototypes earns a **trained shared control** in a separate evidence-bearing multi-question workload. A perfect verifier restricted to this top five cannot exceed 99.00% known closed accuracy on this CLINC development fold; real verification will be worse and may cost too much. The strong gain demonstrates that candidate representation was consequential here, but bare intent names are an unusually weak comparison for a classifier trained on 100 utterances per class. This task has single short utterances, not shared documents or independent questions, and its public templates may leak into training. Audit near-duplicate families and evaluate a document-level dataset before claiming architectural improvement; leave CLINC locked test sealed. Do not describe this as beating Laya, Kev or other decision models.
